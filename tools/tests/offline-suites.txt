# WHY A CURATED LIST. tools/tests/ holds 117 *-selftest.sh files and `.github/workflows/`
# mentioned them only inside COMMENTS ("Proven offline by tools/tests/svc-exitcode-selftest.sh"
# and five more of that shape). So `test` going green said nothing about any of them, and every
# receipt in the register held only as long as someone kept running them by hand. That is
# SELFTESTSUNRUNINCI.
# HOW THIS LIST WAS BUILT - measured, not guessed. Each candidate was first excluded statically

# remained were then RUN, serially, on 2026-10-15; the 40 that exited 0 are listed, plus
# offline-runner-selftest.sh, written afterwards to prove this list's own runner (17 checks).
# A suite is in this file because it was observed to pass, not because it looked portable.
# SERIALLY, AND THAT IS NOT A STYLE CHOICE: blockclaim-selftest.sh reported "10 passed, 2 failed"
# when run in the same command as logvol-lib-selftest.sh and "12 passed, 0 failed" alone, twice -
# both bind and delete loop devices and loop numbers are global (BLOCKCLAIMSELFTESTRACES). A
# parallel runner would reintroduce that false red.
# NOT LISTED, and why - these four are RED at the release sha (0c6d54b8 / agent 5c483cd9), each
# asserting that a fix is absent from the source. They are registered as SUITESREDATRELEASE, not
# silently dropped: a suite left out of CI because it fails is the thing this file exists to stop.
