- **WHAT A FRESHLY CREATED QUBE SHOWS IS WHATEVER THE GUEST REPORTS.** Read from dom0's installed `qubesappmenus`: entries shown = the `menu-items` feature, else `/etc/qubes/applications/<vm>/whitelisted-appmenus.list`, else EVERYTHING reported; a fresh AppVM inherits `menu-items` from its template's `default-menu-items`, and `receive.py` never takes a default from the guest. A whitelist can therefore only ever be a SUBSET of what we report, so an entry we do not report can never be enabled by anyone - which is why this service reports everything and leaves the selection to dom0. `create_template()` ignores the guest's `Exec=` line for a guest that has `qubes.StartApp` (ours does) and launches `qubes.StartApp+<id>`, writes `Name=%VMNAME%: <Name>` (the name is only a label), and asserts the id contains no space, `;` or `%`. The only keys it accepts at all are Name, GenericName, Comment, StartupWMClass, Categories, Exec, Icon - **there is no `NoDisplay` or `Hidden`**, so "report it but hide it by default" is not available to the guest. [verified 2026-10-07]
- **The reported menu was 38 entries, 20 of them one folder - and the first fix for it was wrong.** MEASURED by running the service on a clone of the win11de-qwt golden (German 25H2 26200.8037, no third-party software), and confirmed a second time on a headless clone with the pre-fix script as the control: 38 entries, 20 of them from `Administrative Tools`; `Microsoft Edge` reported TWICE (the built-in dedup compared ids, `Microsoft_Edge` vs `edge`, never the displayed name); names carrying their folder as a prefix ("Windows PowerShell Windows PowerShell ISE"). **The first fix EXCLUDED that folder from the report, and that was wrong**: what this service reports IS dom0's available list, both selection paths only narrow it, so those 20 became impossible for anyone to enable. Owner: *"you silently dropped most of the apps and tell me that it is fine?"* Reverted. What ships: every shortcut is reported (37 available - the old 38 less the duplicate Edge), the displayed name is the shortcut's own with a folder-prefix then numeric fallback so no two entries read alike, built-ins yield on id *or* name, and the service LOGS a suggested `menu-items` value (17 of 37) that an admin can hand to dom0. The default selection is a dom0 feature and a stated prerequisite, exactly like `vmexec` and `qrexec_timeout`; see docs/QVM-FEATURES.md. [verified 2026-10-07]
- **dom0 only ever receives ASCII, and that broke the duplicate check on German guests.** `Emit-Entry` strips non-ASCII because dom0 decodes each line as ASCII and drops the rest, so "Zubeh&ouml;r" arrives as "Zubehr" - and keying the collision check on the RAW name compared a character dom0 never sees. Keying on the sanitised name then exposed a second hole: the disambiguator could only fall back to a folder prefix, and two shortcuts at the Programs root have none, so they still emitted one identical label. The namer now tries bare name, then folder-prefixed, then a bounded numeric suffix. Found by `tools/tests/appmenus-selftest.sh`, not by reading. [verified 2026-10-07]
