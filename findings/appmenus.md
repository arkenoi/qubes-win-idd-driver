- **WHAT A FRESHLY CREATED QUBE SHOWS IS WHATEVER THE GUEST REPORTS.** Read from dom0's installed `qubesappmenus`: entries shown = the `menu-items` feature, else `/etc/qubes/applications/<vm>/whitelisted-appmenus.list`, else EVERYTHING reported; a fresh AppVM inherits `menu-items` from its template's `default-menu-items`, and `receive.py` never takes a default from the guest. A whitelist can therefore only ever be a SUBSET of what we report, so an entry we drop can never be enabled by anyone. `create_template()` ignores the guest's `Exec=` line for a guest that has `qubes.StartApp` (ours does) and launches `qubes.StartApp+<id>`, writes `Name=%VMNAME%: <Name>` (the name is only a label), and asserts the id contains no space, `;` or `%`. The only keys it accepts at all are Name, GenericName, Comment, StartupWMClass, Categories, Exec, Icon - **there is no `NoDisplay` or `Hidden`**, so "report it but hide it by default" is not available to the guest. [verified 2026-10-07]
- **The reported menu was 38 entries, 20 of them one folder.** MEASURED by running the service on a clone of the win11de-qwt golden (German 25H2 26200.8037, no third-party software): 20 of the 28 scanned shortcuts came from `Administrative Tools` (Registry Editor, services, Event Viewer, iSCSI Initiator, ODBC 32/64, Print Management, dfrgui, ...); "Microsoft Edge" appeared TWICE because the built-in dedup compared ids (`Microsoft_Edge` vs `edge`) and never the displayed name; and names carried the folder as a prefix ("Windows PowerShell Windows PowerShell ISE", "Accessories-System Tools Character Map"). Fixed in `get-appmenus.ps1`: that folder (both spellings) is excluded by whole path COMPONENT, the shortcut's own name is emitted, and built-ins yield on id *or* displayed name. - **dom0 only ever receives ASCII, and that broke the duplicate check on German guests.** `Emit-Entry` strips non-ASCII because dom0 decodes each line as ASCII and drops the rest, so "Zubeh&ouml;r" arrives as "Zubehr" - and keying the collision check on the RAW name compared a character dom0 never sees. Keying on the sanitised name then exposed a second hole: the disambiguator could only fall back to a folder prefix, and two shortcuts at the Programs root have none, so they still emitted one identical label. The namer now tries bare name, then folder-prefixed, then a bounded numeric suffix. Found by `tools/tests/appmenus-selftest.sh`, not by reading. [verified 2026-10-07]
